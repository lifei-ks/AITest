## 实现内容

### 数据模型 `app/entity/models.py`（8 张表）

> 定义文件：`app/entity/models.py`。**统一约定**：JSON 结构一律存 `Text` 字符串（`json.dumps/json.loads` 在 service 层做）；所有表无外键约束，靠手写 `project_id`/`test_case_id` 关联，级联删除在 service 层手动实现。

#### 表关系与数据流转

```
projects（项目，根）
 ├── code_analyses（代码分析结果）
 ├── state_machines（状态机）
 ├── test_cases（测试用例）──── test_case_versions（用例版本）
 │        └── execution_records（执行记录）──── execution_steps（执行步骤）
 └── mindmaps（脑图）

流转：建项目 → 静态分析(code_analyses/state_machines) → 生成用例(test_cases)
      → 编辑(落 test_case_versions) → 执行(execution_records/execution_steps) → 脑图(mindmaps)
```

#### 1. `projects` — 项目表（被测项目的元信息）

作用：一个"被测对象"的入口，后续分析/用例/执行都挂在这张表下。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str(36) PK | `uuid4().hex`，全局唯一 |
| `name` | str(120) | 项目名，必填 |
| `description` | Text | 描述，可空 |
| `source_type` | str(20) | `local_path`（本地路径）/ `git`（Git 仓库） |
| `source_path` | Text | 本地源码绝对路径（git 则是克隆后的目录） |
| `git_url` | str(500) | Git 仓库地址 |
| `git_branch` | str(120) | Git 分支 |
| `tech_stack` | Text(JSON) | `{"backend":"java-spring","frontend":"vue"}`，V3 分析回填 |
| `prd_content` | Text | 需求文档纯文本（上传/粘贴） |
| `target_url` | Text | 被测站点基址，默认 `http://127.0.0.1:8200` |
| `created_at` / `updated_at` | datetime | 默认 utcnow |

#### 2. `code_analyses` — 代码分析表

作用：一次静态分析任务的输入输出快照，记录分析状态与结构化事实（供生成用例取用）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str(36) PK | 分析任务 id |
| `project_id` | str(36) 索引 | 所属项目 |
| `status` | str(20) | `pending`/`running`/`success`/`failed` |
| `backend_result` | Text(JSON) | 后端解析结果（端点/实体/枚举/规则/文案） |
| `frontend_result` | Text(JSON) | 前端解析结果（页面/表单/选择器/文案） |
| `warnings` | Text(JSON 数组) | 分析过程中的提示（如未识别到前端） |
| `error_message` | Text | 失败原因 |
| `created_at` | datetime | 创建时间 |

#### 3. `state_machines` — 状态机表

作用：从后端源码提取的业务状态机（如订单 `OrderStatus` 的流转），是生成"流转类用例"的依据。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str(36) PK | |
| `project_id` | str(36) 索引 | 所属项目 |
| `name` | str(120) | 状态机名（通常 = 枚举名） |
| `states` | Text(JSON) | `[{"name":"CREATED","label":"待支付"}]` |
| `transitions` | Text(JSON) | `[{id,from,to,trigger,verified,evidence,guard}]` |
| `confidence` | float | 置信度 |

#### 4. `test_cases` — 测试用例表（核心）

作用：平台最核心的数据，结构化测试用例；既是生成产物，也是执行输入。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str(20) PK | 全局唯一，格式 `TC-{6位递增}` |
| `project_seq` | int | 项目内序号，从 1 起，删除不回收（复合索引） |
| `project_id` | str(36) 索引 | 所属项目 |
| `title` | str(255) | 用例标题 |
| `module` | str(120) | 业务模块，如"订单" |
| `type` | str(20) | `positive`/`negative`/`boundary`/`state` |
| `priority` | str(10) | `P0`~`P2` |
| `preconditions` | Text(JSON 数组) | 前置条件 |
| `steps` | Text(JSON 数组) | 步骤（人话，用于展示） |
| `expected_results` | Text(JSON 数组) | 预期结果 |
| `structured_steps` | Text(JSON 数组) | 结构化步骤（执行器消费，见 6.3.2） |
| `test_data` | Text(JSON 对象) | 测试数据 |
| `coverage_refs` | Text(JSON) | `{"endpointIds":[],"transitionIds":[],"ruleIds":[]}` 覆盖引用 |
| `source` | str(20) | `rule`/`ai`/`manual`/`import` |
| `confidence` | float | 0~1 |
| `quality_score` | int | 0~100 质量分 |
| `lint_issues` | Text(JSON 数组) | 质量闸 Linter 发现的问题 |
| `execution_status` | str(20) | `not_run`/`passed`/`failed`/`skipped` |
| `created_at` / `updated_at` | datetime | |

#### 5. `test_case_versions` — 用例版本表

作用：每次编辑用例自动落一个版本快照，支持回滚。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str(36) PK | |
| `test_case_id` | str(20) 索引 | 所属用例 |
| `version` | int | 从 1 递增（回滚也产新版本，不回退号） |

#### 6. `execution_records` — 执行记录表

| 字段 | 类型 | 说明 |

| `status` | str(20) | `running`/`passed`/`failed`/`skipped`/`cancelled` |

| `target_url` | Text | 执行目标站点 |

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str(36) PK | |

作用：把用例集渲染成的四层树（模块→类型→用例→前置/步骤/预期）的持久化。

| 字段 | 类型 | 说明 |

#### 关键设计决策

1. **JSON 字段统一存 Text**：SQLite 对 JSON 列支持有限，快照类字段需原样保存，序列化交给 service 层。
2. **无外键约束**：用 `project_id`/`test_case_id` 手写关联，级联删除在 `project_service.delete_project` 手动做（有测试断言零残留）。
3. **`test_case_snapshot` 强制非空**：TASK_BOOK 4.6 强调——用例被改/删后，历史报告必须能精确复现证据链。

### 后端 API（8 个接口，全部统一信封）

- `GET/POST /api/projects`（keyword 搜索、创建校验：local_path 必填 sourcePath、git 必填 gitUrl）
- `GET/PUT/DELETE /api/projects/{pid}`（404→code 40401；删除**级联清理** 6 张子表）
- `PUT/GET /api/projects/{pid}/prd`、`POST .../prd/upload`（.md/.txt 直读、.pdf 用 pypdf、.docx 用 python-docx、非法扩展名→40004）
- 响应统一 camelCase（`ProjectOut` + `to_camel` 别名生成器），`analysisStatus` 派生字段已预留（V3 回填）

### 前端（可体验功能）

- **项目列表页** `/projects`：卡片网格、关键词搜索、新建/编辑对话框（本地路径与 Git 类型切换表单）、删除确认（提示级联影响）、点击卡片进详情
- **项目详情页** `/projects/:id`：概览（descriptions 信息卡 + 分析状态标签）+ PRD tab（在线编辑保存 + 文件上传解析）；「代码分析/用例生成/测试用例」tab 置灰，按计划 V3/V4/V5 开放

## 如何体验（现在就可以操作）

服务已启动，浏览器打开 **http://127.0.0.1:5173/**

1. **新建项目**：右上角「新建项目」→ 名称「演示订单系统」→ 源码类型「本地路径」→ 随便填个路径（如 `D:/tmp/demo-src`）→ 保存
2. **搜索**：输入关键词回车过滤
3. **编辑**：卡片「操作 → 编辑」改名字/被测地址
4. **详情**：点击卡片 → 概览信息卡；切到「需求文档 (PRD)」tab → 粘贴一段文字保存；或上传一个 .md/.txt 文件看解析效果
5. **删除**：卡片「操作 → 删除」→ 确认
6. 也可打开 http://127.0.0.1:8100/docs 在 Swagger 里直接调接口

停止服务：`Get-Process node,python | Stop-Process`（或重启后再跑 `scripts/dev.ps1`）
