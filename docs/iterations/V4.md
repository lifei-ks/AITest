## 关键设计决策

1. **决策**：必填字段用后端 `@NotBlank/@NotNull` 注解推断。**理由**：Vue 的 required 常写在 `<script>` rules 里，前端解析器（只扫 template）拿不到（order-system 实测踩到）。
2. **决策**：boundary 约束按"字段+rule"去重。**理由**：DTO 与实体复用相同约束，否则同字段生成 3 条重复边界用例。
3. **决策**：去重阈值 0.95（TASK_BOOK 建议 0.85）。**理由**：规则生成同类型用例标题仅字段名不同，0.85 会误杀"收货人为空/手机号为空"这类合法用例。
4. **决策**：`TC-{6位}` 编号用**数字比较 + flush**，不用 `MAX(id)` 字符串字典序。**理由**：`TC-000010` 字符串序 < `TC-000002`；且 `autoflush=False` 时未 flush 的 pending 用例不可见，导致每次都算出 `TC-000001`（主键冲突）。
5. **决策**：module 名优先取有中文映射的领域实体（Order→订单），状态机名去 Status 后缀再映射。

## 过程修复的问题（真实项目暴露）

1. Vue 必填信息在 `<script>` rules 里 → 前端解析器 required 全 False → 正例/反例生成 0 条
2. 多实体同名字段约束 → boundary 重复生成 → 约束去重
3. 去重阈值 0.85 误杀字段不同的用例 → 提至 0.95
4. `TC` id 字符串字典序 + autoflush=False → 主键冲突 → 数字比较 + flush
