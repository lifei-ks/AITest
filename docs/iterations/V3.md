## 本版目标

Spring Boot + Vue 源码纯规则静态解析（端点/实体/枚举/业务规则/表单/选择器/文案）+ 状态机提取（setStatus 证据 + 守卫推导 + BFS），分析结果落库并提供接口与前端分析页。

## 关键设计决策

1. **决策**：端点正则只匹配 Get/Post/Put/Delete/Patch，`@RequestMapping` 单独处理前缀。**理由**：否则类级 `@RequestMapping` 会被当成端点导致 `/api/orders/api/orders` 重复拼接（实测踩到）。
2. **决策**：枚举常量正则加 `\b`。**理由**：否则构造方法 `OrderStatus(String label)` 会被误当枚举值。
3. **决策**：路由文件只建 `page_name→route` 映射，`.vue` 文件产出真正的 page（含 forms）。**理由**：路由文件没有表单内容，若也产 page 会覆盖 .vue 的 page；无 `<el-form>` 的纯列表页也要产出 page。
4. **决策**：`verified=true` 唯一判据是找到 `setStatus` 写入点。**理由**：TASK_BOOK 4.3 铁律，找不到证据绝不猜。
5. **决策**：Git 项目暂不做 clone，分析仅支持 `local_path`。**理由**：避免扩大范围（TASK_BOOK 10 禁止），git 分支留待需要时再补。

## 过程修复的问题

1. `@RequestMapping` 混入方法级正则 → 端点前缀重复拼接
2. 枚举构造方法被误当枚举值（states 6 个 → 修后 5 个）
3. `.vue` 无 `<el-form>` 页面被过滤 → 纯列表页丢失
4. 状态机样本 `receive`（无守卫写 COMPLETED）制造脏边 → 改为 `create` 写初始态 CREATED
5. PowerShell 脚本 `$pid` 只读变量冲突（V2 的 `$home` 同类问题）

## 真实项目回归（order-system，2026-10-19 追加）

用你的真实项目 `scripts/order-system`（13 Java + 3 Vue）跑了一次分析，结果与暴露的问题：

**正确解析的部分**：技术栈识别 ✓；10 个带 path 的端点 ✓；`OrderStatus` 6 态枚举 ✓；6 条业务规则（守卫+中文消息）✓；状态机主链路 5 条转换（支付/发货/完成/取消/退款）全部 verified ✓；3 个前端页面 + 路由关联 ✓；7 个选择器 + 6 条文案 ✓。

**暴露的 5 个解析问题（样本未覆盖）→ 全部已修复（TDD 闭环）**：

| # | 问题 | 根因 | 修复方式 | 回归测试 |
|---|---|---|---|---|
| 1 | 无括号注解漏解析 | 端点正则要求注解后必须带 `(` | `METHOD_MAPPING_RE` 括号改可选，path 空时继承类级前缀 | `test_bare_mapping_endpoints` |
| 2 | 实体过度识别 | 仅凭"类名大写+有 private 字段"判定 | 加 `NON_ENTITY_SUFFIXES`（Controller/Service/Repository/Exception/Response…）过滤 | `test_entities_exclude_controllers_and_services` |
| 3 | 多约束只留最后一个 | 约束注解逐个覆盖 pending，未累积 | pending 改列表累积，同字段多个注解全保留 | `test_multiple_constraints_kept` |
| 4 | 创建写初始态产生脏边 | 把"对象初始化"误当状态流转 | 目标态 == 初始态（枚举第一个值）时跳过 | `test_no_transition_to_initial_state` |
| 5 | 空 form-item 产生空字段 | 未过滤无 prop 的 form-item | 无 prop 且无 label 的 form-item 不产字段 | `test_no_empty_form_fields` |

修复后 order-system 重新分析结果：**12 端点（补回 create/list）、3 实体（过滤掉 5 个非数据模型）、约束完整（receiverName 保留 notblank+size）、状态机 5 条转换（与 OrderStatus 枚举注释的"5 条合法边"完全一致）、无空字段**。
