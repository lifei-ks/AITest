## 关键修复（e2e 暴露的 4 个坑）

1. **断言锚点全 skipped**：`「」`是中文角括号 U+300C/U+300D，引号正则误写英文弯引号 U+201C/U+201D → 锚点永远提取不到
2. **state 前置步骤用"推进到XX"找不到元素**：改为 BFS 路径反查真实按钮文字（支付/发货）
3. **boundary 漏填其他必填字段**：`other.required`（前端字段全 False）→ 改用后端 `@NotBlank` 推断
4. **submit 后 500ms 跳转断言等不及**：state_assert 前加 800ms 等待

## 铁律验证（不假绿）

- 断言用"操作成功文案"（如「支付成功」）而非状态 label——因为初始数据里就有"已支付"订单，用 label 会假绿
- 无锚点的断言 → 诚实 skipped（不算通过）
